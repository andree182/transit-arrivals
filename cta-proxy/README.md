# cta-proxy — the Transit Arrivals worker

A single Cloudflare Worker that proxies and normalizes arrivals + alerts for **all non-MTA agencies** in Transit Arrivals. New York MTA is the exception: the phone JS fetches the MTA GTFS-RT feeds directly. The name "cta-proxy" is historical (it began as a CTA-only proxy); renaming it would break the deployed URL (`https://cta-proxy.david-torcivia.workers.dev`), so it stays.

## Routes

```
GET /health                          -> "ok"
GET /:agency/arrivals?station=X      -> { epoch, model: [...] }     (CTA also accepts legacy ?mapid=)
GET /:agency/alerts?routes=A,B,C     -> { alerts: [...], suspensions: [...] }
```

`:agency` is one of the keys in the `AGENCIES` map in `src/index.js` (`cta`, `wmata`, `marta`, `bart`, `mbta`, `septa`, `gcrta`, `miami`, `baltimore`, `skyline`, `patco`, `trenurbano`; `lametro` is a stub). An upstream failure never 500s — arrivals fall back to `{ epoch, model: [] }` and alerts to `{ alerts: [], suspensions: [] }`, with a structured `console.log` for observability.

## Response contract

Arrivals are normalized to one shape regardless of agency:

```json
{
  "epoch": 1760000000,
  "model": [
    { "line": "Rd", "color": [200, 16, 46],
      "directions": [ { "label": "", "dest": "Howard", "times": [120, 540], "exp": false } ] }
  ]
}
```

`rtmodel.js` builds this from GTFS-RT TripUpdates for feed-based agencies; JSON-API agencies (CTA, WMATA, MARTA, BART) map into it directly.

## Caching

`cached()` in `src/shared.js` wraps every handler: it checks the Cloudflare Cache API for the request URL, otherwise builds the response and stores it via `ctx.waitUntil`. TTLs are short and set in `src/index.js`: **25 s for arrivals, 60 s for alerts** (also emitted as `cache-control: max-age`).

## Agency module pattern

Each file in `src/agencies/` exports the same surface:

- `arrivals(env, station, now)` → `{ epoch, model }`
- `alerts(env, routes)` → `{ alerts, suspensions }`
- `ROUTE_MAP` — agency route id → `{ label, color: [r,g,b] }` (rail routes only; everything else is dropped)

Most modules also export pure `transform()` / `transformAlerts()` functions so the feed parsing is unit-testable without network. Static data (station → stop_id fanout, names, timetables) lives in sibling `*-data.json` / `*-schedule.json` files generated by `tools/` builders. To add an agency: write the module, import + register it in the `AGENCIES` map in `src/index.js`.

PATCO and Tren Urbano have no real-time feeds; their `arrivals()` computes departures from a bundled GTFS timetable (`src/schedule.js`). GCRTA's GTFS-RT feed is open — no key.

## Secrets

Set each with `wrangler secret put NAME` (from this directory):

| Secret | Agency | Notes |
| --- | --- | --- |
| `CTA_KEY` | Chicago CTA | Train Tracker API key — required |
| `WMATA_KEY` | Washington WMATA | required |
| `MARTA_KEY` | Atlanta MARTA | required |
| `BART_KEY` | SF BART | optional — falls back to BART's public demo key |
| `MBTA_KEY` | Boston MBTA | optional — raises rate limits, sent as `x-api-key` |
| `MIAMI_KEY` | Miami-Dade (Swiftly) | not yet set — module returns an empty board without it |
| `BALTIMORE_METRO_KEY` | Baltimore MDOT MTA Metro (Swiftly) | not yet set |
| `BALTIMORE_LR_KEY` | Baltimore MDOT MTA Light Rail (Swiftly) | not yet set |
| `HONOLULU_KEY` | Honolulu Skyline | not yet set — module returns an empty board without it |

Miami, Baltimore, and Skyline (Honolulu) are fully wired here but **hidden client-side** (the `NOT_YET_LIVE` set in `src/pkjs/lib/stations.js`) until their keys land. GCRTA, SEPTA, PATCO, and Tren Urbano need no secrets.
